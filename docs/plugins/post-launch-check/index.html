post-launch-check v0.1.0

Run the Timedoor after-launch checklist against the live site. A Playwright runner crawls the site and runs the checks it can verify, Claude reviews the judgment rows from the captured evidence, and you get a report you can sync to Notion.

Install

/plugin install post-launch-check@qa-skills

First time? Add the marketplace: /plugin marketplace add backend-timedoor/qa-skills (see Getting started). Then run this in your project:

/setup-post-launch-check

What it checks

TypeMeaningExamples
autoThe script decides pass or failmeta tags, headings, OG, robots, HTTPS, 404, links, images, PageSpeed
reviewClaude judges from captured evidencetitles, alt text, breadcrumb, URL slugs
manualA human checks, with the steps listedFigma colors and fonts, responsive layout, contrast

Post-launch expectations

  • robots.txt allows crawling
  • Meta robots is index, follow
  • Google Analytics script is present (confirm numbers with the PM)
  • PageSpeed mobile at least 55 and desktop at least 85

Run it

run the post-launch-check skill

Output goes to launch-check/post/<date>/ (report.md, report.json, evidence.json).

Notion sync (optional)

Results sync to a separate checklist database with the properties Check, Key, ID, Phase, Site, Group, Status, Pages affected, Evidence, Reviewer and Run date. Set NOTION_TOKEN and NOTION_CHECKLIST_DB_ID in .env, and ask for a dry run first. Testers' edits to Status are never overwritten by a later sync.
