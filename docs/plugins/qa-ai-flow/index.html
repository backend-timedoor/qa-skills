qa-ai-flow v0.1.0

Turn Figma designs into test cases, upload them to Notion, and generate Playwright automation that traces back to each test case.

Install

/plugin install qa-ai-flow@qa-skills

First time? Add the marketplace: /plugin marketplace add backend-timedoor/qa-skills (see Getting started). Then run /setup-qa-ai-flow in your project.

What it does

StepSkill / scriptOutput
0. Setupsetup-qa-ai-flowconfig, .env, e2e/ scaffold
1. Test casesfigma-testcase-generator (Figma, PRD)testcases.json, docs/test-cases/*.md
2. Notionnotion-testcase-uploader (runs upload_testcases_to_notion.py)one Notion page per test case
3. Automationplaywright-from-testcasesPage Objects + specs with // TC-ID comments
4. Resultsnotion-testcase-uploader (sync mode)Status Automation in Notion
  • Every test case keeps one tc_id from generation to Notion to the spec comment.
  • Built for Laravel admin/API, Next.js or Vue.js frontends, and WordPress landing pages. Other stacks work too; the auth and API templates are examples to adjust.
  • Works without repo access: discovery can use a staging URL or the Figma file.
  • Missing data-testid values are reported, never invented.
  • Re-check mode revises test cases when a design or PRD changes.

Prerequisites

  • Node 18+ and Playwright (installed by setup)
  • Python 3.9+ with requests
  • Notion integration token and database ID, for upload (see scripts/GET_NOTION_CREDENTIALS.md)
  • Optional: Figma remote MCP server with a Dev or Full seat and file access

Workspace after setup

your-project/
├── CLAUDE.md                    # QA rules the skills follow
├── qa-ai-flow.config.json       # paths, stagingUrl, apiBaseUrl (gitignored)
├── .env                         # Notion token (gitignored)
├── testcases.json               # from step 1
├── docs/test-cases/             # readable test cases
└── e2e/
    ├── .env.test                # app URLs and test users (gitignored)
    ├── pages/  tests/  helpers/  fixtures/
    └── playwright.config.ts

How to use each skill

Use them in order the first time. Each skill reads the previous step's output, so you only need to name the page or module.

  • 1. setup-qa-ai-flow
  • 2. figma-testcase-generator
  • 3. notion-testcase-uploader
  • 4. playwright-from-testcases

1. setup-qa-ai-flow

When: once per project, before anything else. Safe to re-run; existing files are kept, never overwritten.

/setup-qa-ai-flow

What happens:

  1. Checks Node, Python and requests.
  2. Creates CLAUDE.md, qa-ai-flow.config.json, .env, e2e/.env.test and the e2e/ Playwright scaffold, then installs Playwright.
  3. Asks for your stagingUrl and apiBaseUrl. No repo access is fine.

Then you: fill in .env and e2e/.env.test yourself. Never paste tokens into the chat.

2. figma-testcase-generator

When: you have a Figma screenshot (or a PRD) and need test cases. Best with one section per image; a very long page screenshot should be split first.

Example prompts:

Generate test cases from this screenshot of the login page
Generate test cases for the checkout form. Here is the PRD text and the Figma link.

What happens:

  1. Asks once if you have a PRD (paste text or a .md/.txt file). Requirement IDs from the PRD are reused when it has its own numbering.
  2. Asks a few context questions, and reads the Figma file if you gave a link and have access. Without access it analyses the screenshot only.
  3. Writes test cases covering UI elements, states, interactions, edge cases and accessibility.

Output: docs/test-cases/[page].md (readable) and testcases.json (project root). Every test case gets a stable tc_id such as TC-001.

Re-check mode (no image needed) when a design or requirement changed:

Re-check test cases for the Card component, its states changed

It finds the matching test cases by module name, shows old vs new one at a time, and writes back only the ones you approve. tc_ids stay the same. It does not touch Notion or Playwright files.

3. notion-testcase-uploader

When: testcases.json exists and you want one Notion page per test case, or want to update or sync results later. Needs NOTION_TOKEN and NOTION_DATABASE_ID in .env, and the database shared with your integration.

Example prompts:

Check what test cases are already in Notion
Upload testcases.json to Notion
Update TC-045 and TC-046 in Notion after the re-check
Sync Playwright results to Notion

What happens:

  1. Upload: lists what is already there, shows a dry run, and asks you to confirm. Try one test case first (--limit 1) on a new database. Existing tc_ids are skipped, so it never duplicates.
  2. Update: only the TC IDs you name. Manual Status Chrome/Firefox/Safari values are never overwritten.
  3. Sync results: reads the Playwright JSON report and writes Pass/Fail/Skipped into Status Automation. Tests without a // TC-xxx comment are listed as untraceable.

Database columns and errors: see the uploader guide.

4. playwright-from-testcases

When: test cases are ready and you want Playwright tests for a module.

Example prompts:

Turn testcases.json into Playwright tests for the Login module
Automate the test cases in docs/test-cases/checkout.md

What happens:

  1. Asks how to discover the app: repo source, a live staging URL, or the Figma file when the page is not built yet. It saves the answer in qa-ai-flow.config.json.
  2. Writes an implementation brief per module in e2e/automation-instructions/[module].md and tracks progress in _progress.md.
  3. Detects the auth method before writing any login helper.
  4. Writes Page Objects in e2e/pages/ and specs in e2e/tests/. Each test() carries a // TC-001 comment.
  5. Reports elements that have no data-testid. It never invents or renames them.

Check the result:

cd e2e && npx playwright test --list

Good to know: in Figma mode (no real page yet) it stops after the Page Object and writes no spec, because selectors cannot be verified without a real DOM.

Full example run

  1. /setup-qa-ai-flow
  2. "Generate test cases from this screenshot of the login page" (attach image)
  3. "Upload testcases.json to Notion"
  4. "Turn testcases.json into Playwright tests for the Login module"
  5. Run the tests, then "Sync Playwright results to Notion"
