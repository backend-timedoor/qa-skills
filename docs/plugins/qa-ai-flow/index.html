qa-ai-flow v0.1.0

Turn Figma designs or Strapi schemas into test cases, upload them to Notion, and generate Playwright automation that traces back to each test case.

Install

/plugin install qa-ai-flow@qa-skills

First time? Add the marketplace: /plugin marketplace add <ORG>/qa-skills (see Getting started). Then run /setup-qa-ai-flow in your project.

What it does

StepSkill / scriptOutput
0. Setupsetup-qa-ai-flowconfig, .env, e2e/ scaffold
1. Test casesfigma-testcase-generator (Figma, PRD) or strapi_generate_testcases_v2.py (Strapi Admin)testcases.json, docs/test-cases/*.md
2. Notionupload_testcases_to_notion.pyone Notion page per test case
3. Automationplaywright-from-testcasesPage Objects + specs with // TC-ID comments
  • Every test case keeps one tc_id from generation to Notion to the spec comment.
  • Works without repo access: discovery can use a staging URL or the Figma file.
  • Missing data-testid values are reported, never invented.
  • Re-check mode revises test cases when a design or PRD changes.

Prerequisites

  • Node 18+ and Playwright (installed by setup)
  • Python 3.9+ with requests
  • Notion integration token and database ID, for upload (see scripts/GET_NOTION_CREDENTIALS.md)
  • Optional: Figma remote MCP server with a Dev or Full seat and file access

Workspace after setup

your-project/
├── CLAUDE.md                    # QA rules the skills follow
├── qa-ai-flow.config.json       # paths, stagingUrl, apiBaseUrl (gitignored)
├── .env                         # Notion token (gitignored)
├── testcases.json               # from step 1
├── docs/test-cases/             # readable test cases
└── e2e/
    ├── .env.test                # app URLs and test users (gitignored)
    ├── pages/  tests/  helpers/  fixtures/
    └── playwright.config.ts

How to use

Generate test cases from this Figma screenshot for the login page
Upload testcases.json to Notion
Turn testcases.json into Playwright tests for the login module
Re-check test cases for the Card component, its states changed
