qa-estimation v0.1.0

Estimate the tester man-hours for an inquiry from its PRD, spec, notes and module list, fill the Tester (hrs) column of the Timedoor quotation workbook, and build a QA breakdown workbook to go with it. The estimate assumes AI-powered, black-box QA: test cases are generated from the PRD and reviewed, and testers verify what users and admins can see.

Install

/plugin install qa-estimation@qa-skills

First time? Add the marketplace: /plugin marketplace add backend-timedoor/qa-skills (see Getting started). The scripts need Python 3 and openpyxl:

pip install openpyxl

Run it

Open Claude Code in the inquiry folder (PRD, spec, notes, module list and *Quotation-Context.xlsx) and ask, for example:

buatkan man hours QA untuk inquiry ini dan isi kolom Tester di quotation

Claude reads every document, asks about scope differences (for example a module that is in the PRD but not in the quotation), estimates each task row, and shows the numbers before writing anything.

How the hours are built

RuleWhat it means
Per task rowTester hours = writing/reviewing test cases + one execution cycle, sized by the scenarios in the PRD, not by FE hours.
Black-boxSignatures, idempotency, retries, log sanitising, load tests and backups go to developers or DevOps (0 tester hours, noted in the Notes column).
Test onceIntegrations (payment, shipping, third-party APIs) are tested end-to-end on the page that shows the result; the integration rows get 0 with a pointer.
Critical retestRetest & regression only for money, price, points and order-status modules (50%), auth, RBAC and master data (25%), plus a final E2E regression.

Output

  • The Tester (hrs) and Notes cells of the quotation's Quotation sheet. Nothing else is touched, a backup is made first, and the Timeline sheet's formulas stay intact.
  • qa-manhours-<project>.xlsx: test scope, test case, execution and retest hours per module, an internal buffer, calendar duration and editable assumptions.

Review and trim

Ask Claude to review an existing estimate (cek apakah ada yang tumpang tindih dan bisa dipangkas). Each proposal is tagged as an overlap with another module, outside black-box, or too loose, and nothing is written until you confirm.
